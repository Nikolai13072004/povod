# Развёртывание POVOD на Render

Пошаговая инструкция: PostgreSQL, backend и frontend на бесплатных планах Render.

Порядок обязателен: база → backend → frontend → возврат к backend. Причина в
последнем шаге — адреса сервисов становятся известны только после их создания,
а backend должен знать адрес frontend и наоборот.

---

## Прежде чем начинать

Три ограничения бесплатных планов Render. Ни одно не мешает показать проект, но
знать о них нужно заранее.

| Ограничение | Что это значит |
| --- | --- |
| **База живёт 30 дней** | По истечении срока Render её **удаляет**, а не замораживает. Дату видно на странице базы. |
| Backend засыпает через 15 минут простоя | Первый запрос после сна идёт ~50 секунд. Дальше нормально. |
| 1 ГБ на базу | Пока картинки хранятся base64 внутри строк, это ~150 событий с фото (MEDIA-001). |

Запиши дату удаления базы в календарь. Данные с бесплатного плана не
восстанавливаются.

---

## Шаг 1. PostgreSQL

**New → Postgres**

| Поле | Значение |
| --- | --- |
| Name | `povod-db` |
| Region | **Frankfurt (EU Central)** |
| PostgreSQL Version | 17 |
| Instance Type | Free |
| Storage | 1 GB |

Storage Autoscaling и High Availability оставить выключенными.

Регион важен: база и backend в разных регионах не увидят друг друга по
внутренней сети.

После создания на странице базы найди блок **Connections** и скопируй
**Internal Database URL** — понадобится на следующем шаге.

> Именно Internal, не External. Внутренний адрес не выходит в интернет и не
> тарифицируется как трафик.

**Миграции применять руками не нужно.** Backend прогоняет их сам при старте под
advisory-блокировкой, поэтому одновременный запуск двух экземпляров безопасен.

## Шаг 2. Backend

**New → Web Service** → подключить репозиторий `povod`.

| Поле | Значение |
| --- | --- |
| Name | `povod-api` |
| Region | **Frankfurt** — тот же, что у базы |
| Root Directory | `backend` |
| Runtime | Node |
| Build Command | `npm ci --include=dev && npm run build` |
| Start Command | `npm start` |
| Health Check Path | `/health/ready` |
| Instance Type | Free |

`/health/ready` действительно проверяет доступность базы, а не только живость
процесса, — поэтому Render не отправит трафик на экземпляр, который поднялся,
но до базы не достучался.

**`--include=dev` обязателен.** Переменная `NODE_ENV=production` заставляет npm
пропускать dev-зависимости, а компилятор TypeScript и `@types/node` лежат
именно там. Без флага сборка падает на `error TS2688: Cannot find type
definition file for 'node'`. Убрать `NODE_ENV=production` вместо этого нельзя:
на нём держатся защиты конфигурации — запрет демо-входа, запрет почтового
транспорта, пишущего в лог, и требование явного `CORS_ORIGIN`.

### Переменные окружения

```
NODE_ENV=production
DATABASE_URL=<Internal Database URL из шага 1>
CORS_ORIGIN=https://povod-web.onrender.com
APP_URL=https://povod-web.onrender.com
AUTH_COOKIE_SAMESITE=none
AUTH_COOKIE_SECURE=true
DEMO_AUTH_ENABLED=false
MAIL_TRANSPORT=smtp
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=<полный адрес ящика>
SMTP_PASSWORD=<пароль приложения, не пароль от почты>
MAIL_FROM=POVOD <тот же адрес, что в SMTP_USER>
ENABLE_EXTERNAL_EVENTS=true
```

### Как выбрать транспорт почты

| Транспорт | Когда |
| --- | --- |
| **`brevo`** | **На бесплатном Render — единственный работающий.** HTTP API, домен не нужен: подтверждается один адрес отправителя, 300 писем в сутки |
| `resend` | Есть свой домен. Письма с `no-reply@домен`, лучшая доставляемость |
| `smtp` | Хостинг выпускает SMTP наружу. На бесплатном Render — **не работает**, см. ниже |
| `none` | Восстановление пароля осознанно отключено |

**Render с сентября 2025 блокирует исходящий трафик на SMTP-порты (25, 465, 587)
для бесплатных сервисов.** Соединение уходит и не возвращается:

```
Error: Connection timeout   code: 'ETIMEDOUT'   command: 'CONN'
```

Выглядит так, будто не отвечает почтовый сервер, — но дело в хостинге, и
настройками SMTP это не обходится. Порт 587 закрыт наравне с 465. Выходов два:
платный тариф Render либо транспорт поверх HTTP (`brevo`, `resend`).

**Важно про `brevo`: подтверждённого отправителя мало.** Транзакционная отправка
у новых аккаунтов выключена до ручной проверки — антиспам-мера. Ключ при этом
рабочий, письмо просто отклоняется:

```
Brevo отклонил письмо: 403 — {"message":"Unable to send email. Your SMTP account
is not yet activated...","code":"permission_denied"}
```

Включается через тикет в поддержку (значок `?` в шапке → **Support and
tickets**). В тикете просят адрес сайта, тип писем (transactional, не
marketing) и ожидаемый объём. Ответ приходит за 1–2 рабочих дня.

**Важно про `resend` без домена:** он доставляет письма **только на адрес
владельца аккаунта**. Любой другой получатель не получит ничего, и в логе будет
отказ провайдера. Для проекта без домена это означает «работает только у меня».

**Важно про `smtp`:** нужен **пароль приложения**, а не пароль от почты —
обычный ни Яндекс, ни Gmail для SMTP не принимают. И `MAIL_FROM` обязан
совпадать с `SMTP_USER`: чужого отправителя провайдеры отклоняют. Конфигурация
проверяет это на старте.

`CORS_ORIGIN` и `APP_URL` пока указывают на ещё не созданный сервис. Это
нормально: точный адрес узнаем на шаге 3 и вернёмся сюда.

**`PORT` задавать не нужно** — Render подставляет его сам, конфигурация его
читает.

### Почему `AUTH_COOKIE_SAMESITE=none`

Это единственная настройка, без которой вход **молча** перестанет работать —
без ошибки в логах и без сообщения на экране.

Frontend и backend живут на разных поддоменах `onrender.com`. Домен
`onrender.com` входит в Public Suffix List, поэтому браузер считает
`povod-web.onrender.com` и `povod-api.onrender.com` **разными сайтами**. Кука
сессии со значением `SameSite=Lax` (по умолчанию) к таким запросам не
приложится: сервер увидит анонима, фронт — «вы не вошли».

`SameSite=None` требует `Secure`, иначе браузер отбрасывает куку вообще. На
старте это проверяется: конфигурация с `none` без `secure` не запустится.

Если позже фронт и API переедут на общий домен (`povod.ru` и `api.povod.ru`),
верни `lax` — он строже.

## Шаг 3. Frontend

**New → Static Site** → тот же репозиторий.

| Поле | Значение |
| --- | --- |
| Name | `povod-web` |
| Root Directory | `frontend` |
| Build Command | `npm ci && npm run build` |
| Publish Directory | `dist` |

### Переменные окружения

```
VITE_API_URL=https://povod-api.onrender.com
VITE_DEMO_AUTH_ENABLED=false
```

Адрес backend возьми со страницы сервиса из шага 2. Render добавляет к имени
случайный суффикс (`povod` превращается в `povod-v1fg.onrender.com`), поэтому
угадать адрес нельзя — только скопировать.

> Переменные `VITE_*` **вшиваются в сборку**. Изменить их и просто перезапустить
> сервис недостаточно — нужен новый деплой (Manual Deploy → Deploy latest
> commit).

### Правило перезаписи (обязательно)

**Settings → Redirects/Rewrites → Add Rule**

| Source | Destination | Action |
| --- | --- | --- |
| `/*` | `/index.html` | Rewrite |

Без этого правила прямая ссылка на `/page-1/<id>` или обновление страницы по
F5 отдадут 404: на диске такого файла нет, маршрутизация живёт в браузере.

Именно `Rewrite`, а не `Redirect`: адрес в строке должен остаться прежним.

## Шаг 4. Свести адреса

Вернись в **povod-api → Environment** и приведи две переменные к настоящему
адресу frontend:

```
CORS_ORIGIN=https://<реальный адрес povod-web>
APP_URL=https://<реальный адрес povod-web>
```

`CORS_ORIGIN` — точный origin, без пути и без завершающего слэша. Значение `*`
в production отклоняется на старте: с `credentials: include` браузер всё равно
откажется принимать ответ со звёздочкой, и вход не заработает.

`APP_URL` — из него собираются ссылки в письмах восстановления пароля.

Сохрани — Render перезапустит сервис сам.

## Проверка

По порядку, каждый пункт зависит от предыдущего:

1. `https://<api>/health/ready` → `200`. Если `503` — backend не видит базу,
   смотри `DATABASE_URL`.
2. `https://<api>/api/Events` → JSON со списком событий. Значит миграции
   применились и посев прошёл.
3. Открыть frontend → страница входа.
4. Зарегистрироваться. **Тут проверяется куки-настройка**: если после
   регистрации снова видно экран входа — не выставлен
   `AUTH_COOKIE_SAMESITE=none`.
5. Создать событие, перезагрузить страницу — событие на месте.
6. Открыть событие, скопировать адрес, вставить в новую вкладку — открывается,
   а не 404. Это проверка правила перезаписи.
7. «Забыли пароль?» → свой адрес → письмо приходит.

## Досягаемость из России

Проверь отдельно: открой адрес frontend **с телефона по мобильному
интернету**, а не по домашнему Wi-Fi.

Render раздаёт `*.onrender.com` через Cloudflare, а российские провайдеры с
июня 2025 ограничивают трафик к Cloudflare первыми 16 КБ. Если страница не
грузится или грузится наполовину — дело в этом, а не в коде.

Тогда нужен хостинг без Cloudflare перед ним: Timeweb Cloud, Selectel,
Yandex Cloud. Приложение при этом не меняется — тот же Docker-образ и те же
переменные окружения.

## Если что-то не работает

| Симптом | Причина |
| --- | --- |
| Сборка падает на `TS2688: Cannot find type definition file for 'node'` | В Build Command нет `--include=dev`; `NODE_ENV=production` выкинул dev-зависимости |
| Вход проходит, но страница снова просит войти | `AUTH_COOKIE_SAMESITE` не `none` |
| `CSRF token missing or invalid` после входа | Версия backend старше SEC-016: на разных доменах фронт не может прочитать CSRF-куку API |
| В консоли браузера ошибка CORS | `CORS_ORIGIN` не совпадает с адресом frontend буква в букву |
| Прямая ссылка на событие даёт 404 | Нет правила перезаписи `/*` → `/index.html` |
| Первый запрос идёт минуту | Бесплатный сервис спал, это ожидаемо |
| `502` сразу после деплоя | Сервис ещё поднимается, смотри Logs |
| Сервис не стартует, в логах жалоба на переменную | Конфигурация отклоняет небезопасные production-настройки намеренно — в тексте ошибки написано, какую именно |
| Письма не уходят | При `resend` без подтверждённого домена они идут только на адрес владельца аккаунта — возьмите `smtp` |
| SMTP отвечает «Invalid login» | Нужен пароль приложения, а не пароль от почты |
| Письма не уходят, в логе `ENETUNREACH` и адрес вида `2a00:...` | Хостинг без исходящего IPv6, а почтовый сервер отдаёт AAAA. Приложение разрешает имя в IPv4 само — обновите backend |
