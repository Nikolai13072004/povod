# POVOD

POVOD — full-stack сервис поиска, создания и социального планирования локальных событий. Это самостоятельное web/PWA-приложение с дополнительными интеграциями в социальные экосистемы: VK Mini Apps, Telegram, MAX и другие платформы при наличии подходящего официального API.

## Возможности MVP

- лента, поиск и фильтрация событий;
- создание события, запись и отмена записи;
- комментарии, профиль и интересы пользователя;
- собственная регистрация, вход и отзываемые серверные сессии;
- платформенно-независимое ядро с адаптерами социальных платформ;
- VK Bridge и вход через launch-параметры VK;
- импорт публичных концертов и фестивалей из KudaGo;
- карта события на OpenStreetMap.

## Структура

```text
frontend/  React + Vite + TypeScript + VKUI + MobX
backend/   Express + TypeScript + Zod + normalized PostgreSQL
```

## Быстрый локальный запуск

В двух отдельных терминалах:

```bash
cd backend
npm ci
npm run dev
```

```bash
cd frontend
npm ci
# Создайте frontend/.env.local с VITE_API_URL=http://localhost:8080/
npm run dev
```

Backend доступен на `http://localhost:8080`, frontend — на `http://localhost:5173`.

### Запуск всего стека через Docker

После установки Docker Desktop из корня репозитория выполните:

```bash
docker compose up --build
```

Команда поднимет PostgreSQL, API и собранный frontend. Приложение будет доступно по
`http://localhost:5173`, API — по `http://localhost:8080`. Данные PostgreSQL сохраняются
в локальном Docker volume; для полной очистки окружения используйте `docker compose down -v`.

Для локального демо-входа Docker Compose подготавливает пользователя
`elmira@povod.app` с паролем `povod-demo`. Демо-учётные данные явно отключаются
в production через `DEMO_AUTH_ENABLED=false`.

## Документация

Общие документы намеренно дублируются в `frontend/` и `backend/`, чтобы обе части приложения можно было развивать независимо:

- `CHANGELOG.md` — история изменений;

## Принцип интеграций

События, пользователи, участие и комментарии принадлежат POVOD и хранятся в его API и базе данных. Социальные платформы используются как дополнительные каналы авторизации, запуска, уведомлений, приглашений и шаринга; ни одна из них не является обязательной для работы продукта.

## Статус

MVP собирается и проходит проверку типов. Локальный стек запускается через Docker Compose,
PostgreSQL использует нормализованную схему с миграциями, а «Мои события» загружаются
с сервера. Собственная браузерная авторизация и проверка прав выполняются backend.
События используют ISO 8601 и IANA timezone, а интерфейс локализует дату и время.
Основные сценарии событий имеют единые состояния загрузки, ошибки с повтором и
пустого результата. Ближайшая задача — унифицировать конфигурацию окружения и
добавить автоматическую проверку API-контракта.
