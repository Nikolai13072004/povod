# POVOD

**Сервис поиска, создания и социального планирования локальных событий.**
Самостоятельное web/PWA-приложение: собственные пользователи, события и данные, а
социальные платформы (VK Mini Apps, Telegram, MAX) подключаются как дополнительные
каналы входа и шаринга — ни одна из них не обязательна для работы продукта.

## Что умеет

**События**

- лента с поиском и фильтрами (интересы, дата, время, место), состояние фильтров переживает переходы;
- создание повода с фото, категориями и выбором «публичное / закрытое»;
- **редактирование и удаление** собственного события с подтверждением;
- запись и отмена записи, счётчик участников выводится из реальных связей;
- комментарии с модерацией автором события;
- **экспорт в календарь** (`.ics` — Google Calendar, Apple Calendar, Outlook);
- приглашение по прямой ссылке на конкретное событие;
- карта места на OpenStreetMap;
- импорт публичных концертов и фестивалей из KudaGo.

**Люди**

- регистрация и вход по email с отзываемыми серверными сессиями;
- профиль на сервере: имя, город, аватар, интересы;
- **публичный профиль автора** с его открытыми событиями (без раскрытия email);
- «Мои события» с вкладками «Созданные» / «Посещаю» и счётчиками;
- друзья.

## Технологии

```text
frontend/  React 18 · Vite · TypeScript · VKUI · MobX · Emotion
backend/   Express · TypeScript · Zod · PostgreSQL (нормализованная схема + миграции)
```

Хранилище выбирается конфигурацией: PostgreSQL (production), JSON-файл или in-memory
(разработка и тесты) — за общим интерфейсом репозитория.

## Быстрый запуск

### Через Docker (рекомендуется)

```bash
docker compose up --build
```

Поднимет PostgreSQL, API и собранный frontend. Приложение — `http://localhost:5173`,
API — `http://localhost:8080`. База заполнится демо-данными автоматически.

**Демо-вход:** `elmira@povod.app` / `povod-demo` (в production отключается через
`DEMO_AUTH_ENABLED=false`).

### Без Docker

```bash
cd backend  && npm ci && npm run dev    # :8080, in-memory хранилище
cd frontend && npm ci && npm run dev    # :5173
```

Настройки — в корневом `.env` (образец: `.env.example`). Backend валидирует переменные
через Zod **до** запуска: в production запрещены wildcard CORS и демо-вход.

## Качество

Каждый Pull Request проходит GitHub Actions: форматирование, линт, проверка типов,
тесты и production-сборка — плюс отдельная джоба с **реальным контейнером PostgreSQL**.

```bash
npm run check     # format + lint + typecheck + тесты + сборка
npm run check:api # smoke-проверка API-контракта на запущенном сервере
```

- **Тесты:** unit и API на backend, интеграционные против настоящей PostgreSQL
  (миграции с нуля, транзакции, конкурентность), Vitest + React Testing Library на frontend.
- **Надёжность:** graceful shutdown, раздельные liveness/readiness пробы, React Error Boundary,
  транзакции с блокировкой строк для составных операций.

## Безопасность

- пароли — `scrypt`; в базе хранится только SHA-256-хэш токена сессии;
- сессии отзываемые, истёкшие удаляются регулярной задачей;
- проверка прав владельца на изменение событий, комментариев и профиля — с
  регрессионными тестами на horizontal privilege escalation;
- приватные события скрыты от посторонних, email не отдаётся в публичных ответах;
- `helmet`: CSP, `X-Content-Type-Options`, frame policy, HSTS в production;
- загружаемые изображения проверяются **по сигнатуре файла**, а не по заявленному
  клиентом MIME; SVG запрещён, размер ограничен;
- rate limit на эндпоинтах входа;
- централизованная **редакция секретов и персональных данных в логах** (токены,
  пароли, подписи, учётные данные в connection-строках, email).

Как сообщить об уязвимости — в [`SECURITY.md`](SECURITY.md).

## Принцип интеграций

События, пользователи, участие и комментарии принадлежат POVOD и живут в его API и
базе. Социальные платформы — дополнительные каналы авторизации, запуска, приглашений
и шаринга. Приложение полностью работоспособно без любой из них.

## Статус

MVP работает: полный сценарий от регистрации до создания события, участия и
обсуждения. Схема PostgreSQL нормализована и покрыта миграциями, права проверяются на
сервере, даты хранятся как ISO 8601 с IANA timezone и локализуются в интерфейсе.

**В работе:** публичный деплой, дизайн-система с тёмной темой, перенос сессии в
`HttpOnly`-cookie, пагинация ленты и OpenAPI как единый контракт API.
