# Работа с POVOD

Этот документ одинаков в обоих репозиториях и задаёт общие правила работы с одним full-stack продуктом.

AI-агенты также обязаны следовать `AGENTS.md`: он прямо определяет порядок чтения документации и обязательное обновление общего журнала изменений.

## Перед началом

1. Убедитесь, что frontend и backend находятся на согласованных ветках.
2. Для локальной разработки используйте отдельные `.env` / `.env.local`; секреты никогда не коммитятся.
3. Перед изменением API посмотрите `ARCHITECTURE.md` и текущий контракт в коде.

## Правила изменений

- Одна ветка — одна осмысленная задача.
- Не смешивайте исправление продукта, массовое форматирование и обновление зависимостей в одном изменении.
- При изменении API обновляйте frontend и backend согласованно.
- При добавлении завершённой функции, исправлении ошибки или изменении архитектуры обновляйте оба `CHANGELOG.md`.
- При изменении планов обновляйте оба `ROADMAP.md`.

## Проверка перед коммитом

Backend:

```bash
npm run typecheck
npm test
```

Frontend:

```bash
npm run build
```

## Что документировать

В `CHANGELOG.md` записываются изменения, заметные пользователю или разработчику. В `ARCHITECTURE.md` — изменения границ модулей, хранения данных, API и интеграций. В `ROADMAP.md` — только актуальные планы и их статус.
